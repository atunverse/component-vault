# ComponentVault · DIY 物料库存

安卓端的物料库存管理应用：电子元器件、五金标准件、工具、3D 打印耗材，一套流程管完。
手机即服务端，电脑在同一局域网用浏览器就能管库存。

## 功能

| 模块 | 能力 |
|---|---|
| 物料域 | `电子` / `五金` / `工具` / `3D耗材` / `其他` 五个域，共用一套库存逻辑 |
| 快速录入 | 电子件查立创自动补全；五金先翻译成标准件规范名再查；耗材按克管理；立创没有的手填 |
| 详情页 | 点整行进详情：图标、参数、库存、仓位、立创商品页、数据手册、库存流水 |
| 编辑 | 仓位 / 分类 / 单位 / 阈值 / 单价 / 参数 / 立创号都能改；**数量只能走出入库** |
| 图标 | 入库时自动下载立创官方图并缩到 192px 存本机；没有收录的可以拍照或从相册选 |
| 库存检索 | 按物料域 + 分类筛选 + 关键词检索（型号/规格/标签/仓位/内部编号），点**数量**直接出入库 |
| BOM 分析 | 粘贴 BOM（每行「型号,数量」），自动比对库存并标出齐备 / 不足 / 缺失 |
| 局域网管理 | 手机开前台服务，电脑浏览器访问 `http://手机IP:8080`，含缩略图、改仓位、REST API |
| 流水审计 | 数量变动记 before / after / delta（带幂等键）；资料修改记一条 `EDIT` 并写清改了哪些字段 |

## 五金与 3D 耗材怎么处理

### 五金：先规范名，再检索

立创的检索是关键词模糊匹配，**对规范名极准、对口语极不准**（2026-10-20 实测）：

| 输入 | 命中总量 | 前几条实际返回 |
|---|---|---|
| `螺丝` | 20,793 | 理线器、插拔式接线端子 ❌ |
| `M3螺丝` | 28,051 | PCB 焊接端子 ❌ |
| `DIN912 M3` | 30 | 全部「内六角圆柱头螺钉」✅ |
| `铜柱` | 1,603 | 单头六角铜螺柱 ✅ |
| `M3螺母` | 2,287 | 六角螺母 ✅ |

所以录入 `M3*8` 时不是直接查，而是：

```
M3*8 → 解析（M3 / 8mm）→ 补默认(内六角圆柱头 · DIN912 · 304) → DIN912 M3×8
     → 裁成检索词「DIN912 M3」→ 立创 → 按长度过滤
```

检索词刻意不带长度：带长度会漏掉 `M3-0.5X8` 这种写法。

五金件的商品页是 `item.szlcsc.com/mro/{id}.html`，用数字 id 构造后浏览器会自动跳转，
所以和电子件共用一套链接逻辑。

### 3D 耗材：立创没有，纯本地

实测搜 `PLA 1.75mm` / `PETG 1.75` 返回的是**固态继电器和 LED 数码管**——
立创 EDA 元件库不收录耗材，所以不做联网补全，按克（`g`）管理，
参数里存「净重」，详情页按 `剩余 / 净重` 画进度条。

### 立创 MRO 站（mro.szlcsc.com）

工业品确实在那边，但 **App 不抓取**：其搜索页返回软 404、API 网关被腾讯 EdgeOne WAF 拦成 403
（实测），和之前网页爬取撞瑞数 WAF 是同一个问题。所以只在详情页给一个「立创工业品」外链让人自己逛。

## 补全是怎么做到的

不依赖网络也能出结果，靠的是**分层降级**：

1. **内置型号库** —— 约 35 个高频型号的完整参数（SS34、AO3400、AMS1117-3.3、STM32F103C8T6、CH340C 等）
2. **型号规则解析** —— 这部分是核心，纯本地推导：
   - 三位容码：`104` → 100nF、`103` → 10nF
   - 三位阻码：`103` → 10kΩ
   - 四位阻码：`1002` → 10kΩ
   - R 记法：`4R7` → 4.7Ω、`R47` → 0.47Ω
   - EIA-96：`01C` → 10kΩ（完整 96 码表）
   - 带单位：`10K` → 10kΩ、`100N` → 100nF、`4.7UH` → 4.7µH
   - 封装识别：`0603` → 0603 (1608)，以及 SOT-23 / SOP-8 / LQFP-48 / SMA 等
3. **立创元件库（联网，免 Key）** —— 返回真实规格参数、封装、品牌、库存、阶梯价、数据手册，以及**立创号与商品页链接**

本地两层先出卡片（毫秒级），联网结果在 350ms 防抖后原地覆盖。断网只影响"填得多不多"，不影响能不能录。

规则推断出的参数在界面上会标注「参数为规则推断值，请核对后再入库」；立创返回的数据不标，因为它是官方值。

### 立创数据源（不需要 API Key）

用的是立创 EDA 专业版元件库的检索接口，**无认证、无 AppKey**：

```
GET https://pro.lceda.cn/api/eda/product/search?keyword=STM32F103C8T6&currentPage=1&pageSize=20
```

实测（2026-10）：

| 项 | 结果 |
|---|---|
| 响应 | `code:200 / ok:true`，返回 `code`(C8734)、`model`、`standard`(封装)、`brandName`、`stockNumber`、`priceList`、`pdfFileUrl`、`device_info.description`(结构化参数) |
| 延迟 | 638–840ms，10 次连续请求 0 失败 |
| 大小写 | 不敏感 |
| 中文 | 支持，`肖特基二极管` 命中 27112 条 |
| pageSize | 至少支持 50 |

> 这是网页端自用的接口，不属于对外承诺的开放平台，**可能变更**。所以字段全给了默认值 + 忽略未知字段，失败自动降级到本地规则。

原先设想的开放平台方案（`ips.lcsc.com`，需企业认证、1000 次/日）已弃用，对应占位代码 `RemoteLcsc.kt` 已删除。

### 立创号 → 商品页链接

**只有一种格式可用**，且不能用立创号拼：

| 格式 | 实测 |
|---|---|
| `item.szlcsc.com/{数字id}.html` | ✅ 200，title 是该器件名 |
| `item.szlcsc.com/{C编号}.html` | ❌ 落到 404 页，但 **HTTP 仍返回 200**（软 404） |
| `www.szlcsc.com/p/{C编号}.html` | ❌ 404 |
| `so.szlcsc.com/global.html?k={C编号}` | ⚠️ 203 瑞数 WAF，浏览器可开，程序不可 |

所以 `Part` 同时存两个标识：`lcscCode`（C8734，业务标识）+ `lcscProductId`（9243，路由标识）。有 ID 拼精确商品页，只有立创号时退化到搜索页。

数据手册：`pdfFileUrl` 是相对路径，拼 `https://atta.szlcsc.com` 即可下载（实测 200、`application/pdf`、2.07MB）。

### 准确性怎么保证

立创搜索是**模糊检索**，直接取第一条会出错。实测反例：

- 搜 `C8734` 返回 14 条，第 2 条是 `DAC8734EVM`（完全不同的器件）
- 搜 `SS34` 返回 404 条，前两条型号都叫 SS34，封装分别是 `SMC(DO-214AB)` 与 `SMA(DO-214AC)`

对策（`enrich/LcscMatcher.kt`，纯函数）：

1. **归一化**：大写 + 去空格/连字符/下划线，保留小数点
2. **分层评分**：立创号相等 1000 > 型号相等 900 > 剥包装后缀相等 850 > 前缀 700 > 包含 550 > 标题含词 300；有货 +20、有手册 +10、有图 +5
3. **立创号精确过滤**：排序后再按 `code` 完全相等筛一次
4. **多封装不合并**：并列展示，由人确认，绝不自动猜

## 测试与验证

```bash
# 单元测试（15 例，纯 JVM，CI 里先跑测试再打包）
gradle :app:testDebugUnitTest

# 链路契约验证：真实请求接口 + 真实打开商品页
node tools/verify-lcsc.mjs
```

契约脚本会输出一张表并给出退出码，任一环节失败返回 1，可挂到定时任务上做巡检。它**不复刻排序逻辑**——排序只在 Kotlin 里有一份实现（被单测覆盖），脚本只验"接口字段还在、链接还能开"，避免两套实现漂移出假绿灯。

## 构建

本机不需要装 Android Studio，GitHub Actions 直接出包。

```bash
# 推送到 main 自动构建
git push origin main

# 产物在 Actions 的 Artifacts 里，或打 tag 生成 Release
git tag v0.1.0 && git push origin v0.1.0
```

本地构建（需 JDK 17 + Android SDK 35）：

```bash
./gradlew :app:assembleDebug
# 输出 app/build/outputs/apk/debug/app-debug.apk
```

### 签名：必须是固定密钥

CI 从仓库 Secret `CI_KEYSTORE_B64` 解码出 `ci-debug.p12` 来签名（PKCS12，别名 `ci`）。
**不能用每次现生成的密钥** —— AGP 在全新 runner 上会自动新建随机 debug.keystore，
结果每个发布的 APK 签名都不同，手机上覆盖安装直接报「应用未安装」，
用户只能卸载重装，库存数据全丢。

证书指纹（CI 里硬校验，不一致直接 fail）：

```
SHA-256: db2af5769c07e8b728756b54e451f11280f10ea0ca5fca869ac34069f1e6027f
```

密钥不入库（`.gitignore` 排除 `*.p12` / `*.keystore`）。换机器或换账号时，
需要重新生成密钥并更新 Secret **和** workflow 里的指纹常量，否则老用户无法升级。

### 三道构建期校验

| 步骤 | 拦什么 |
|---|---|
| `tools/check_manifest.py` | Manifest 里声明的组件类在源码里不存在（编译期不报的坑） |
| `Verify APK launch config` | 成品 APK 的二进制 Manifest 指向的类、dex 里是否真有 |
| `Verify APK signature` | 签名指纹漂移，防止下次更新覆盖安装失败 |

## 安装到手机

1. 下载 `app-debug.apk`
2. 手机允许「安装未知来源应用」
3. 安装后首次启动会灌入 8 条示例数据

局域网功能需要手机和电脑在同一网段；连不上优先查路由器的 **AP 隔离**。

> **从 v0.2.0 升到 v0.2.1 必须先卸载旧版。** v0.2.0 及以前的包是每次临时密钥签的，
> 与本版签名不同，直接覆盖会报「应用未安装」。卸载会清空本地库存（v0.2.0 一启动就闪退，
> 本来也没有数据）。**从 v0.2.1 起签名固定，以后可以正常覆盖升级，数据不丢。**
